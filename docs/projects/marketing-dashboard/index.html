Project overview

Goal

From scattered data
to answers worth exploring

Brought users, traffic, purchases and behavior into one workspace for Sleepal’s pre-launch and crowdfunding campaigns, making channel quality and conversion paths easier to compare.

My role

Defined the product.
Built the full stack with AI.

Independently handled analysis questions, metric definitions, interaction design, data ingestion, database, APIs, frontend and deployment with AI, checking and refining the results throughout.

Outcome

From one-off reports
to a team’s daily tool

Launched an internal dashboard for cross-platform data, source filtering and conversion analysis. Refined it with colleague feedback and later coordinated a maintenance handover.

Start with the team’s questions

Reorganized data from separate platforms around the sources, behavior and conversions the team needed to understand.

Where does traffic come from?

Grouped ref codes, UTMs and existing source labels into readable channel categories, retaining the original codes for traceability.

Are visitors paying attention?

Compared engagement time, bounces, scrolling and devices by source, keeping both the raw data and filtered views available.

Where do visitors stop?

Mapped the main page, engagement, Back, payment and completion page into a journey, then made each step explorable by source.

One person, the entire stack

I defined requirements, broke down tasks and set constraints. AI implemented and iterated; I checked the results.

Turn user needs into technical decisions

The team needed daily access, while APIs such as Clarity had rate limits. I chose scheduled ingestion with historical storage, so filtering queried the database without repeatedly calling source platforms.

Make every change verifiable

Specified sources, fields, calculations and interface behavior before asking AI to implement them step by step. Retained raw counts and checked queries, builds and refresh status to verify the work.

Make the numbers trustworthy

Sum first, then calculate

Aggregated counts across dates and sources before calculating rates, rather than averaging percentages.

Total completion-page sessions ÷ Total sessions = Completion rate in view

Make the filter scope explicit

Category, source code and the >1s filter update the table, sorting and totals together. Users can see which view the numbers describe and return to all data for comparison.

Separate observations from estimates

Displayed completion-page visits, platform attribution and actual orders separately. Revenue derived from completion-page sessions and an adjustable order value was labeled as estimated, not actual revenue.

Show when data was updated

Displayed refresh times by source and checked key tables. Split syncing into independent jobs and retried temporary API errors to make failures easier to locate.

Refine the tool through real use

  1. 05.02—05.03

    From reports to an interactive dashboard

    Established the Klaviyo data pipeline, added the database and APIs, then built a cross-platform interface.

  2. 05.08—05.09

    Open it to the team

    Colleagues accessed the dashboard through work-email verification and requested new dimensions. It became part of daily website and crowdfunding funnel analysis.

  3. 06.12—06.16

    Resolve issues from real feedback

    Addressed source classification, date filters and overlapping tooltips. Investigated fluctuations against GA, checking whether Direct traffic was included and aligning scope before explaining differences.

  4. Mid–late June

    Hand over maintenance, keep improving

    Coordinated a maintenance handover for ongoing support, continued refining refresh jobs and aligned metrics for new guidance events.
